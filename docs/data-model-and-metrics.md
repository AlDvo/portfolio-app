# Спецификация данных и метрик
## Приложение оценки портфеля облигаций и акций

Версия: 0.1 (черновик для обсуждения)
Источник портфеля: отчёт брокера Альфа-Банк (Excel)
Источник рыночных данных: открытый API Мосбиржи (ISS MOEX)

---

## 1. Поток данных

```
Excel-отчёт брокера
       │  1. Парсинг
       ▼
├─ Positions (позиции + средние цены покупки)
├─ Meta (период, клиент, счёт)
       │  2. Для каждого ISIN → обогащение данными MOEX
       ▼
└─ SecurityData (справоч. данные + рынок: цена, НКД, купоны, амортизации, дивиденды)
       │  3. Расчёт
       ▼
└─ PositionMetrics (метрики по каждой бумаге)
       │  4. Агрегация
       ▼
└─ PortfolioMetrics (сводка + календарь денежных потоков)
       │  5. Кэш + отображение
       ▼
    UI (список, карточка бумаги, календарь выплат)
```

## 2. Источник 1 — Excel-отчёт брокера (Альфа-Банк)

Файл: «Брокерский <номер>.xlsx». Листы отчёта: **Динамика позиций**, **Завершенные сделки**, **Незавершенные сделки**, **Движение ДС**, **Неторговые операции**.

### 2.1. Лист «Динамика позиций» → текущие позиции

Структура (заголовки в строках 17–19, данные с ~строки 20):

| Колонка по заголовку | Содержимое |
|---|---|
| Инструмент | категория: «Акции» / «Облигации» / «Прочее» / «Валюта» |
| Актив | название бумаги |
| кол-во на конец периода | количество, шт |
| стоимость на конец периода, руб. | оценка брокера на дату отчёта |
| (кол-во/стоимость на начало периода) | для истории, обычно 0 при новом счёте |
| место учета/хранения | НРД / РЦБ |
| субсчет | номер субсчёта |

Внимание: **ISIN лежит в строке под названием бумаги** (например, строка 23 под названием в строке 22). Парсер: при обнаружении значения, похожего на ISIN (12 символов, формат `[A-Z]{2}[A-Z0-9]{9}[0-9]`), он привязывается к ближайшей позиции выше.

**Выход парсера:**

```ts
interface PortfolioMeta {
  reportPeriodStart: string;    // из шапки: «Отчетный период»
  reportPeriodEnd: string;
  client: string;               // «Клиент»
  agreement: string;            // «Ген. соглашение»
  subaccount: string;           // субсчёт (в отчёте Альфы может быть несколько)
  accountType: 'iis' | 'regular' | 'unknown';  // ИИС / обычный — задаётся вручную в приложении
                                                // (в отчёте не помечен); влияет на налоги в будущем
}

interface PositionRow {
  isin: string;            // из строки под названием
  name: string;            // «Актив»
  category: 'Акции' | 'Облигации' | 'Прочее' | 'Валюта';
  quantityEnd: number;     // кол-во на конец периода
  valueEnd: number;        // стоимость на конец периода, руб. (контрольное значение)
  subaccount?: string;
}
```

Позиции из реального файла (сверка): 9 позиций на сумму 405 223,85 ₽.

### 2.2. Лист «Завершенные сделки» → средняя цена покупки

Заголовок — строка ~15, сделки со строки 16. Колонки (порядок из шапки):

`№ сделки | Дата заключ. | Дата расчетов | Место заключения | ISIN/рег.код | Актив | Количество | Цена | Сумма сделки | В т.ч. НКД | Валюта расчетов | Комиссия банка | Валюта комиссии`

**Критично для парсера:** индексы колонок плавают из-за объединённых ячеек и многострочных заголовков. Парсер должен **искать колонки по нормализованному тексту заголовка** (убрать переносы/пробелы, сравнить с эталонными ключами), а не по фиксированному номеру.

**Выход парсера (агрегат по ISIN):**

```ts
interface PositionCost {
  isin: string;
  buyQty: number;          // Σ кол-ва по buy-сделкам (qty > 0)
  buyCost: number;         // Σ (цена × qty) по buy-сделкам
  buyNkd: number;          // Σ НКД, уплаченного при покупке
  buyFee: number;          // Σ комиссий по buy-сделкам
  netQty: number;          // Σ всех сделок (с учётом продаж) → сверка с позицией
}
```

- **Продажи** (qty < 0) исключаются из расчёта средней цены, но учитываются в `netQty` для сверки.
- **Средняя цена покупки с издержками:**

```
avgPriceNet = (buyCost + buyNkd + buyFee) / buyQty
```

- Сверка: `netQty` из сделок должен совпасть с `quantityEnd` из «Динамики позиций». Расхождение → ошибка/подозрение (неполный файл, делистинг в периоде).

### 2.3. Формат — стабильность

Отчёт Альфа-Банка стабилен по структуре, но заголовки с «⁴ ⁵ ⁶…⁸» и переносами. Нормализация: `NORMALIZE = remove(whitespace, newline, '⁰¹²³⁴⁵⁶⁷⁸⁹')`, сравнение by `startsWith` с эталоном.
Если в будущем понадобятся другие брокеры — каждому свой «профиль парсера» (набор эталонных заголовков). Старт — только Альфа.

## 3. Источник 2 — MOEX ISS (открытый API, без ключей)

Базовый URL: `https://iss.moex.com/iss`. Формат ответа — JSON, параметр `iss.meta=off`.

### 3.1. Эндпоинты

| Что нужно | Эндпоинт (концептуально) | Что берём |
|---|---|---|
| Поиск бумаги по ISIN | `securities.json?q=<ISIN>` | `secid` (торговый код), группа/тип |
| Справочник бумаги | `securities/<secid>.json` | ISIN, название, тип, номинал, валюта, дата погашения, лот, статус |
| Режимы торгов | `securities/<secid>.json` → `boards` | board облигаций (TQOB), акций (TQBR), фондов |
| Купоны + амортизации | `securities/<secid>/bondization.json` | график: дата, купон (₽ или %), тип (фикс/флот), остаток номинала |
| Оферты | `securities/<secid>/offers.json` (при наличии) | дата и цена оферты |
| Дивиденды | `securities/<secid>/dividends.json` | история: дата отсечки, сумма на акцию |
| Текущая цена, НКД | `engines/stock/markets/<shares|bonds>/boards/<board>/securities/<secid>.json` (блок marketdata) | LAST, ACCRUEDINT (НКД), YIELD, статус торгов |
| Курс валют | `statistics/engines/currency/...` | курс USD/RUB и др. |

Детали конкретных board-кодов (TQIF/TQTF для фондов, сплиты точечных полей) уточняются на этапе реализации и проверяются по каждой бумаге портфеля.

### 3.2. Выход — SecurityData

```ts
interface CouponEvent {
  date: Date;            // дата выплаты
  value: number;         // купон, ₽ на бумагу (или % от номинала — конвертируем)
  type: 'fixed' | 'float';
  faceAfter: number;     // номинал в обращении после выплаты (для амортизации)
  isKnown: boolean;      // false для флоатера на будущих периодах
}

interface SecurityData {
  isin: string;
  secid: string;
  name: string;
  securityType: 'bond' | 'share' | 'etf';   // определение по справочнику
  currency: string;                          // RUB / USD / ...
  faceValue: number;                         // номинал (облигации)
  maturityDate?: Date;                       // дата погашения
  board: string;                             // режим торгов

  lastPrice: number;        // чистая цена
  accruedInt: number;       // НКД (облигации)
  tradingStatus: string;    // 'normal' | 'closed' | ...

  coupons: CouponEvent[];   // облигации (с амортизациями)
  amortization: { date: Date; amount: number }[];  // из faceAfter
  offers?: { date: Date; price: number }[];

  dividends?: { exDate: Date; valuePerShare: number }[];  // акции/фонды
}
```

## 4. Позиция — итоговая модель «paper с метриками»

```ts
interface PositionMetrics {
  // ── исходные данные ────────────────────────────────
  isin: string;
  name: string;
  securityType: 'bond' | 'share' | 'etf';
  quantity: number;                 // из отчёта
  avgPriceNet: number;              // (цена+НКД+комиссия)/шт при покупке
  currency: string;

  // ── оценка ─────────────────────────────────────────
  lastPrice: number;                // чистая цена с MOEX
  accruedInt: number;               // НКД (облигации)
  marketValueFull: number;          // (цена + НКД) × кол-во
  costBasis: number;                // avgPriceNet × кол-во
  pnl: number;                      // marketValueFull − costBasis
  pnlPercent: number;               // pnl / costBasis × 100
  weight: number;                   // marketValueFull / Σ(MV), %

  // ── доходность (облигации) ─────────────────────────
  couponYieldCurrent: number;       // текущая купонная доходность, %
  couponYieldSimpleToMaturity: number;  // простая, от цены покупки, %
  ytmMarket: number;                // YTM от рыночной цены, % годовых
  ytmFromPurchase: number;          // YTM от цены покупки, % годовых
  ytpFromPurchase?: number;         // доходность к оферте (если есть), %

  // ── риск (облигации) ───────────────────────────────
  durationMacaulay: number;         // лет
  durationModified: number;         // лет
  dv01: number;                     // ₽ на позицию на 1 б.п.
  gSpread?: number;                 // спред к ОФЗ, б.п. (если кривая доступна)

  // ── дивиденды (акции/фонды) ────────────────────────
  dividendYieldTtm: number;         // выплаты за 12 мес / цена, %
  expectedDividend: number;         // ожидание на акцию/пай, ₽ (ручной ввод)
  dividendIncomeYear: number;       // expectedDividend × кол-во, ₽/год

  // ── денежные потоки (облигации) ────────────────────
  cashFlowToMaturity: {             // все будущие события по позиции
    coupons: number;                // Σ купонов, ₽
    amortization: number;           // Σ амортизаций, ₽
    face: number;                   // номинал при погашении, ₽
    total: number;                  // итого до погашения, ₽
  };
  incomeNext12m: number;            // купоны/дивиденды за 12 мес, ₽

  // ── статус ─────────────────────────────────────────
  status: 'ok' | 'not_found' | 'delisted' | 'no_data' | 'float_assumption';
}
```

## 5. Формулы

Обозначения: `t` — годы от «сегодня» (или от даты покупки) до даты события, `CF_t` — денежный поток в момент `t` (купоны, амортизации, номинал), `P_full = lastPrice + accruedInt`.

### 5.1. Текущая купонная доходность
```
couponYieldCurrent = (сумма купонов за следующие 365 дней × faceValue в обращении) / lastPrice × 100%
```
Для амортизируемых — купоны считаются от остатка номинала (берём из `faceAfter`).

### 5.2. YTM (решение численно, бисекция)

```
P = Σ CF_t / (1 + y)^t
```
- `P` = полная цена: рыночная (для `ytmMarket`) или покупки (`avgPriceNet`, для `ytmFromPurchase`).
- Через `P` = Σ cash flow с учётом амортизаций и номинала на дату погашения.
- Диапазон поиска y: −0.5 … +1.0, точность 1e-6 (или 0.1 б.п.).
- Если потоков до погашения нет (цена выше суммы возврата) — y отрицательный, показываем как есть.

### 5.3. Дюрация Маколи и модифицированная
```
D_mac = Σ (t · PV(CF_t)) / Σ PV(CF_t)          // PV по ytmMarket
D_mod = D_mac / (1 + ytmMarket)
```

### 5.4. DV01 на позицию
```
dv01 = 0.0001 × D_mod × marketValueFull
```

### 5.5. Простая доходность к погашению (от цены покупки)
```
simpleY = ( (Σ купоны до погашения + амортизации + номинал) − P_purchase ) / P_purchase
        × (365 / дней до погашения) × 100%
```

### 5.6. Спред к ОФЗ (G-spread)
```
gSpread = ytmMarket − ytmBenchmark
```
`ytmBenchmark` — интерполяция по дюрации между двумя ближайшими ОФЗ, у которых рассчитан YTM (`D_mod` в диапазоне кривой). Вне диапазона — поле пустое.

### 5.7. Дивидендная доходность (акции/фонды)
```
dividendYieldTtm = (Σ выплат за последние 12 месяцев) / lastPrice × 100%
dividendIncomeYear = expectedDividend × quantity
```
`expectedDividend` по умолчанию = TTM-экстраполяция; ручная корректировка обязательна для осмысленности (в UI — редактируемое поле).

## 6. Портфель — агрегаты

```ts
interface PortfolioMetrics {
  totalValue: number;            // Σ marketValueFull (по всем позициям)
  totalCost: number;             // Σ costBasis
  pnlTotal: number;
  pnlPercentTotal: number;

  // веса и структура
  positions: PositionMetrics[];  // с weight
  weightsByType: { bonds: number; shares: number; etf: number };  // % от стоимости

  // риск
  weightedDuration: number;      // Σ D_mod_i × weight_i (по облигациям)
  portfolioDv01: number;         // Σ dv01_i
  avgYtmBonds: number;           // Σ ytmMarket_i × weight_i (по облигациям)

  // доход
  couponIncome12m: number;       // Σ купонный доход по облигациям за 12 мес
  dividendIncome12m: number;     // Σ дивиденд/выплаты фондов за 12 мес
  totalIncome12m: number;
  totalIncome12mPercent: number; // totalIncome12m / totalValue × 100

  // календарь денежных потоков
  cashFlowCalendar: CashFlowEvent[];
  cashFlowByMonth: { month: string; amount: number }[];  // на 12/24 мес вперёд
}

interface CashFlowEvent {
  date: string;                  // YYYY-MM-DD
  isin: string;
  name: string;
  type: 'coupon' | 'amortization' | 'maturity' | 'dividend';
  amount: number;                // ₽ на позицию
}
```

Календарь строится на 12 месяцев (экран по умолчанию) и до погашения самых длинных бумаг (расширенный вид).

## 7. Экраны (логика показа данных)

1. **Сводка** — итоговая стоимость, P&L, средневзвешенная дюрация, DV01, прогноз дохода на 12 мес (купон + дивиденд + %), список позиций с core-метриками (цена, текущая доходность, YTM, P&L).
2. **Карточка бумаги** — все поля `PositionMetrics`; график купонов/амортизаций; для флоатеров метка «будущие купоны = допущение»; для фондов явно «дюрация не определена».
3. **Календарь выплат** — события по месяцам, суммы по портфелю.

## 8. Допущения и ограничения (должны быть прозрачны в UI)

| # | Допущение |
|---|---|
| A1 | **Дивиденды** — прогноз есть только экстраполяцией (TTM) + ручной ввод. Будущих дивидендов нигде нет. |
| A2 | **Флоатеры** (в портфеле напрямую их нет, но заложить): будущие купоны = последний известный купон, скорректированный пропорционально длине купонного периода (`startdate`→`coupondate` из MOEX). Это учитывает длинные первые купоны (например, СФО МОС МСП: купон за 80 дней → месячные в ~2.6 раза меньше). Если `startdate` неизвестен — без коррекции. RUONIA не моделируется. |
| A3 | **БПИФ/ETF** — дюрация, YTM, G-spread не определяются (нет графика купонов на уровне фонда). Считается только доходность по выплатам (TTM/ручной ввод). |
| A4 | **Налоги не учитываются** (расчёты «до налога»). Счёт может быть ИИС или обычным — налоговый режим различается и не влияет на расчёт в MVP. Тип счёта заложен в модель (ручной ввод, `PortfolioMeta.accountType`) для будущего учёта налогов. |
| A5 | Комиссии учтены в цене покупки; комиссии продажи и депозитарные в MVP не моделируются. |
| A6 | Для СФО и амортизируемых облигаций купон считается от остатка номинала (по `faceAfter` MOEX). |
| A7 | Рейтинг эмитента, P/E, P/B — вне MVP (нет бесплатного API); при желании — ручной ввод. |
| A8 | Цена покупки — средневзвешенная по buy-сделкам (не FIFO). Для частичных продаж даёт приближение. |

## 9. Кэш и обработка ошибок

- **Кэш MOEX**: ответы на день (цены до 18:45 МСК обновляются в течение дня; при следующем открытии приложения — повторный запрос, если дата изменилась). Хранить: `SecurityData` по ISIN + дату запроса.
- **Статусы позиций**: `not_found` (ISIN нет в MOEX), `delisted` (погашена/делистинг), `no_data` (нет торгов), `float_assumption`. Каждая — со своим сообщением в UI, расчёт по остальным продолжается.
- **Разовые ошибки сети** — не блокируют: используются последние кэшированные данные + метка «данные на 05.09».
- **Валидация ISIN** на входе: контрольная сумма (ISO 6166), длина 12.

## 10. Решённые и открытые вопросы

**Решены:**
- G-spread: линейная интерполяция YTM бенчмарка по дюрации между двумя соседними ОФЗ (см. 5.6); вне диапазона кривой — пусто.
- Стоимость брокера используется как контрольное значение; расчёт ведётся по живым ценам MOEX.
- Налоги не учитываются в расчёте (разные типы счетов — ИИС / обычный).
- Цена покупки — средневзвешенная по buy-сделкам с учётом НКД и комиссии (не FIFO).

**Открытые:**
1. Точные board-коды для БПИФ и получение выплат по паям с MOEX (или вручную). Правится на этапе реализации.
2. Дивиденды по Сберу: какой формат VALUE в `dividends.json` MOEX — сумма «до налога» или «чистая». При расчёте без налогов — берём как есть, но помечаем.
3. Нужен ли учёт денег (лист «Движение ДС») в стоимости портфеля (для весов) — MVP по позициям без денег.
